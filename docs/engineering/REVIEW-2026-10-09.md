## 一、从第一性原理看这个产品

用户要的只有一件事：**说清楚想法 → 看一小段 → 点确认 → 拿到视频 → 聊天改**。凡是不直接服务这条链路、或让这条链路更难走通的东西，都是成本。

按这个标准，问题主要不在"某个函数写错"，而在三处结构性矛盾：

1. **系统允许用户走进必然失败的路。** MVP 只能交付 `crayon-book / 16:9 / 20–30 秒`，但：
   - 初始偏好是 45 秒、无画风；
   - 创作助手（director）拿到的是全部 43 种画风，提示词里也没有 MVP 限制；
   - "先看效果"按钮只检查"有主题、有画风"；
   - 真正的限制 `assertMvpProfile` 藏在 Worker 流水线里。
   结果：用户聊完、选了水彩或说"做 45 秒"，按钮是亮的，点了之后排队、启动，然后在 Worker 里以泛化错误失败。这是本次修复的最高优先级业务问题。
2. **证明系统的复杂度远大于产品本身。** 仓库 1143 个文件，其中 345 个证据文件（14MB）、105 个探针/诊断脚本、156 个测试文件；`src` 约 1.1MB，而前端只有约 80KB。冻结包、回执、哈希围栏、未知费用账本层层叠加，每一层都可能让正式发布"按设计失败"（MVP_DELIVERY 记录的漏字阻断、泛化 `PROVIDER_UNAVAILABLE`、未知费用死锁都属于此类）。这些不是 bug，但它们决定了迭代速度。
3. **代码可读性低到影响正确性。** 大量文件是单行压缩写法（一行几百上千字符、439 行超过 300 字符），十几个分支的三元表达式承载错误文案映射。审查与修改都极易出错，本次的多处问题正是藏在这种写法里。

### 交互（已修复）

- 弹窗（画风、我的视频）因 Tailwind 预设重置了 `dialog` 的 `margin:auto`，显示在左上角而不是居中。
- 回复进行中没有任何"正在回复"提示；新增三点动画（不增加 `role=status`，不影响现有 E2E 严格选择器）。
- 移动端"看视频"页签：有新效果/新结果/制作中时显示提示点，避免用户在聊天页错过结果。
- 移动端文案"继续在右边告诉我"在手机上不成立；改为按屏宽显示"右边"或"「聊想法」里"。
- 点示例后自动聚焦输入框；选完画风自动切回聊天并聚焦。
- 效果确认页：把"就按这个做"移到视频正下方，桌面 900px 高度内无需滚动即可确认；视频宽度随视口高度收缩。
- 正式制作中，确认页标题改为"完整视频正在制作。"并隐藏已失效的确认按钮。
- 失败提示移到视频上方，先看到失败再看旧片。
- 连接中断提示用警示色，真实错误用错误色（原来全部是红字）。
- 资料上传：读取中/已读取/失败三态分别有图标与底色；可取消已选未上传的文件。
- "我的视频"列表显示项目阶段（效果待确认/视频已完成…），点击后关闭弹窗。
- 新增四步进度条（聊想法 → 看效果 → 做成片 → 下载与修改），用户随时知道自己在哪一步。

### 视觉（已修复）

实现与 `docs/hand-off/videobuddy-v5.1/design` 原型偏差较大：图标全部用字符（♧ ▷ ↑ ＋），"＋ 新建"按钮文字未垂直居中，助手消息没有署名，下载按钮被 64px 空白推到首屏以外。本次按原型的设计系统重写了 `globals.css`（同一套 token），补齐原型的线性图标、助手署名、加载/错误/状态样式、对话框结构；样式重置改用 `:where()` 零特异性，避免覆盖组件样式。

### 未修复、建议后续处理

1. **压缩写法**：建议引入 Prettier 并一次性格式化（纯格式提交，单独 PR），否则每次审查都在和格式搏斗。
2. **每次状态写入都 spawn 一个 Python 进程**（`FileStore.mutate` → `state_store.py`，只为 `flock`）。单机自托管可以接受，但每个请求多次 fork 是明显的延迟来源；可改为 Node 内进程锁 + 原子 rename，或一个常驻的 Python 写入进程。
3. **错误文案映射**散落在 `route-utils.ts`、`project-store.ts`、`use-project-events.ts`、各 hook 里，同一错误码在不同地方说法不同。建议集中为一张 `errorCode → {status, message}` 表。
4. **`runDirector`（非流式）没有超时**，流式版本有 120 秒超时，行为不一致。
5. **正式发布的内容检查对逐字显现动画过敏**：MVP_DELIVERY 记录的漏字阻断源于提示词允许打字机效果。已在提示词中禁止，但更稳的做法是在内容检查采样时避开文字动画区间，或让标题文字作为独立字幕层而不是画面源码。
6. **证据与探针**：14MB 证据、105 个探针脚本放在主仓库，建议移到单独的 `evidence` 分支或制品存储，主分支只保留可复现的测试。
7. **43 风格目录元数据过期**：`catalog.json` 中 crayon-book 仍是 `deliveryStatus:not_run`、"尚未验证"，与 MVP 已发布正式影片的事实不符。
