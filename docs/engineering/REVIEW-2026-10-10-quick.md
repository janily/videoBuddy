# 第三轮：面向社区的极简出片（2026-10-10）

详见 [QUICK_FLOW](QUICK_FLOW.md)。决策（已与项目负责人确认）：一次出整片、新建精简流水线（旧的分阶段流程保留，`VIDEO_FLOW=staged` 可切回）、配乐用运营方提供的授权曲库、本轮不做登录。

## 本轮做了什么

- **一次出整片**：mvp 模式下点“生成视频”直接得到完整视频，模型调用只有“构思 1 次 + 每镜 1 次”。
  - 复用原有的预览命令、队列、取消和 SSE，接口和前端协议不变，只是 Worker 换成 `runQuickFilmOperation`，完成后直接把成片发布为当前结果。
  - 每一步按输入缓存。
- **竖屏 9:16**：快速流程放开竖屏；助手在用户提到抖音、小红书、视频号时会建议竖屏。播放器按比例显示，桌面上竖屏视频与调整面板左右并排。
- **曲库配乐**：自动按画风和情绪选曲，也可以手动换一首或不要配乐。换配乐只重新混音。
- **AI 生成标识**：画面右上角显示“AI生成”，MP4 元数据写入 `comment` 与 `aigc` 标签。
- **单镜重画**：成片下方列出各镜，可只重画某一镜。
- **画风样片位**：`public/style-samples/<id>.jpg` 放上即显示。
- **视觉模型调用重构**：`runVisualShot` 与新的 `runQuickVisualShot` 共用同一份提示词构建，后者以简单帧时钟代替旁白时间轴。

## 实际验证过的

- 快速流程的纯逻辑测试 7 项、交付门与推荐测试 8 项，用简易测试运行器实际执行，全部通过。其中包括真实的 FileStore + Python 原子写入。
- 第 5 步的 ffmpeg 命令在本机实际运行过，横屏、竖屏、有配乐、无配乐都试过：
  - 输出 30.000 秒、48kHz 双声道；
  - 整片响度 -16.0 LUFS，结尾淡出到 -36 dB；
  - 画面右上角“AI生成”可见，元数据标签写入。
- 前端用真实组件和真实样式截图核对了快速流程的各个状态。

## 没有验证的

- 完整五步没有在真实模型 + Docker 媒体镜像上跑过。这里没有模型密钥、Docker 和 npm 依赖，类型检查和 E2E 也没有跑。
