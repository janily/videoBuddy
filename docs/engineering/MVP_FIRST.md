# 当前研发优先级：先交付可用 MVP

2026-10-05，依据用户最新指示：“整体就是要先跑通核心目标和MVP”。本文件决定当前研发顺序，高于历史增量记录和原计划的逐模块扩展顺序。原 v5.1 文档和43风格完整范围保留，MVP通过不等于C2完整交付。

## 审查结论

问题主要在执行顺序，也在文档的阶段边界表达：入口将C2写成最终完成标准，实施计划虽要求T05–T14先做垂直闭环，实际工作却不断扩展全量素材、质量证明及恢复基础。没有把一个能从页面完成的C1闭环设为下一次交付的硬目标。

已完成的工程可以复用，不重写、不换框架。当前700项测试不能证明用户闭环。以浏览器实际成功走完一次为当前衡量标准。

### 代码中的直接阻断

1. `src/components/video-studio/result-stage.tsx:28`：“就按这个做”按钮无条件disabled，且没有批准点击处理。后端已有`preview/approve`路由，但用户无法通过当前页面启动正式制作。
2. `src/services/video/quality/approved-delivery.ts`：所有完整交付规则先置blocking/not_checked；即便Visual返回pass，`visual_review`仍被固定成not_checked。若无旁白之外的情况，听感等规则也未被本函数填入合格证据。`quality/delivery.ts`又强制全部规则，因此正常正式流水线无法自然发布结果。这不是单纯缺一个按钮。
3. `src/services/video/budget/model-budget.ts`：未知计费状态会阻断共享gate；当前Critic真实超时见`evidence/clear-full-film-critic-probe.json`。需要有可操作的失败恢复路径，不能长期把一笔未知费用变成全部后续研发的死锁。保留未知费用记录，不能伪造usage/退款或换空账本绕过。
4. README和任务表混有较早实现状态，当前交接文档反复追加历史细节，却缺少简明的下一交付目标。原Vercel条款与已批准的自托管替代也容易混读。当前采用既有自托管架构，不重新引入Blob/Sandbox凭据。

## 本阶段唯一交付目标

用户在已确认的页面输入一个新主题，拿到真实生成的视频；可以预览、确认、播放、下载，再通过聊天修改并获得新版本。全过程使用正常API、Worker和持久状态，不能靠CLI手改控制态、伪造批准或把技术探针复制成正式结果。

MVP支持范围：

- 文字需求为主，已有Markdown可用路径继续保留；不以新增全模态支持作为首片前置条件。
- 先验收已有真实产物基础的`crayon-book`风格，横屏、20–30秒、中文旁白与字幕，720p预览、1080p成片。其他风格代码/规则保留，未验证能力明确标识，不宣称已可用。
- 保留既定视觉、右侧聊天、单输入、SSE、持久消息、刷新恢复、私有资源访问与任务状态。
- 一次真实预览确认，正式结果可播放、下载MP4；一次文字内容修改可走新预览及确认，旧视频仍可下载。MVP不要求所有修改都实现safe-direct优化。
- 失败有明确说明和可恢复操作；取消后不发布迟到结果，不重复自动启动状态未知的媒体生产器。

## 当前执行队列

1. **打通发布前提。** 基于当前实现明确版本化的MVP质量策略：实际文件/解码/尺寸时长、字幕与语音、来源和许可、已知内容错误等必须有相应真实证据；补齐可直接复用的检测。C2的审美、完整听感和多轮全风格认证独立记录，不把缺失检查写成pass，也不让尚无实现的认证规则使MVP永久不可完成。不得修改旧冻结包来迁就新策略。
2. **解除可恢复模型失败的死锁。** 根据既有不限次数/费用的授权，设计并测试有上限的新attempt、明确未知成本占用与不重复发布规则；旧unknown保留。不得将未知媒体状态按已停止处理。此条是待实施的策略变更，本审查未修改gate或发起调用。
3. **接批准→结果→下载。** 接通按钮、客户端提交/重连、既有批准API、Worker和发布。校验旧预览过期、重复点击、失败重连。不是仅移除disabled。
4. **真实新主题跑通。** 浏览器从空项目开始，用实际模型、配音、渲染完成预览、按钮确认、正式结果和MP4下载；保存完整操作结果及真实产物。
5. **跑通一次修改和恢复。** 聊天修改一句标题或内容，生成新预览/新片，验证旧版保留；刷新或重启Worker后消息/结果可恢复，SSE断开不取消制作。
6. **交付可使用的MVP。** 提供启动命令、实际访问地址、成片下载、已支持范围和剩余事项。补一个英文或无旁白案例后再按原文档宣称C1；不把MVP等同全部C2。

## 研发节奏约束

- 每项工作必须能说明它解除上面哪一步阻断；无直接关系就进入后续待办。
- 不再以“继续完善T05所有来源”作为下一步，也不以全部43风格完成作为首个可用产品的前提。
- 修改时跑相关行为测试；集成里程碑再跑完整测试/构建/E2E。不要将全量构建与重文件I/O集成测试并行。文档小改不重跑700项测试。
- 不重复启动已完成的媒体工作仅为了增加证据；未知外部调用不盲目重试。新attempt必须有明确恢复设计。
- 已有音频试听确认继续有效，不逐片逐句重复询问。仍保留一次正式预览确认的产品交互。
- 保持无数据库、无登录、真实服务、私有存储和隔离执行。不自动push或生产部署。
