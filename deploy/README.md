# Single-host deployment draft

The web, Director worker and PDF source worker run as the same unprivileged Unix user so their mode-0600 state files are shared. Only the worker units receive the `docker` supplementary group; the web unit cannot open the Docker socket. The Docker group is a privileged host capability, so worker code and group membership must be controlled. These units are templates for a Linux host, not a completed production deployment or a substitute for T21 acceptance.

1. Install Node 22, Python 3 and Docker Engine on one Linux host with persistent local disk. Put a reviewed release under `/opt/videobuddy/current`, owned by root and readable by `videobuddy`; do not make source or `node_modules` writable by the service user. Run `npm ci`, `npm run build`, and the full repository checks before switching a release. Configure an HTTPS reverse proxy to `127.0.0.1:3000` and forward the original `Host` and `Origin` headers.
2. Build `runtime/media/Dockerfile` for that host architecture. Record `docker image inspect --format '{{.Id}}' videobuddy-media:local`; set `VIDEO_MEDIA_IMAGE_REF` to that immutable `sha256:...` ID and `VIDEO_MEDIA_RUNTIME_DIGEST` to the 64 hex digits after the prefix. Use the release's media probe and independent QA before enabling generation. Preserve package license notices from the image.
3. Create `/var/lib/videobuddy` mode `0700`, owned by `videobuddy`. Put non-world-readable settings at `/etc/videobuddy/video.env` (mode `0600`), based on `.env.local.example`; set `VIDEO_DATA_DIR=/var/lib/videobuddy` and the public HTTPS `VIDEO_APP_ORIGIN`. Never put model/session keys in unit files. Keep `VIDEO_GENERATION_ENABLED=false` until every required product gate passes.
4. Install the three unit files, review the host-specific paths, and start them only under a separate deployment authorization. The web unit has no Docker group. The source worker performs text-layer PDF extraction even while paid generation is disabled; it uses the same pinned media image. Verify two cold processes, worker heartbeat, SSE reconnect, a real PDF and media probe, backup/restore, and private access on the target host. Limit external traffic at the reverse proxy and expose only HTTPS.

For a consistent backup, stop all three services, copy `/var/lib/videobuddy` to protected storage with metadata preserved, then restart and check both worker leases. Restore to an isolated host first and run project, message, SSE and artifact checks before claiming the backup usable. A copy made while writes continue has no proven cross-file snapshot consistency. Production procedures, monitoring, retention cleanup and rollback drills are still pending in T20/T21.
