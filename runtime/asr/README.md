# Offline speech recognition runtime

Run `python3 runtime/asr/fetch_model.py`, then build `docker build -t videobuddy-asr:local runtime/asr`. The fetcher pins a specific [faster-whisper-small model revision](https://huggingface.co/Systran/faster-whisper-small/tree/2ec96c5472da50d38d40c0cfe0602af2e94b4c8a) and verifies four SHA-256 hashes. Model weights stay outside Git. The model card states MIT; the [faster-whisper project](https://github.com/SYSTRAN/faster-whisper) is also MIT. `requirements.lock` pins the Python runtime dependencies.

Record `docker image inspect videobuddy-asr:local --format '{{.Id}}'` in `VIDEO_ASR_IMAGE_REF`, with the 64 hex characters in `VIDEO_ASR_RUNTIME_DIGEST`. The container is called with no network and receives only the WAV and a language value, never the expected words. `zh-CN` and `en` verify generated lines; `auto` detects the language of uploaded speech and only accepts Chinese or English. `npm run probe:video:asr -- --record` exercises fresh Chinese and English speech, text matching, word timestamps and same-stage replay. `npm run probe:video:source-audio -- --record` exercises a real upload, conversion, auto detection and source publication. Both probes need the pinned offline voice image; the source probe also needs the pinned media image.

The model can misrecognize a clean sentence. A mismatch blocks the line; the application must retain the original expected words and arrange a new synthesis or trusted review. Word timings are model estimates. Uploaded speech up to 120 seconds is split into overlapping windows and blocked when sustained audible content has no transcript. A 56.525-second varied synthetic recording passed that coverage gate, while a 52-second repeated sentence failed it. This does not establish transcript accuracy: the model misheard names and words in the successful sample. Listening QA, human recordings and subtitle alignment remain separate release gates.

To select the larger fixed model, run `python3 runtime/asr/diagnostics/fetch-medium.py` from the repository root, then `docker build -f runtime/asr/Dockerfile.medium --build-context medium_model=.video-local/asr-medium/model -t videobuddy-asr:medium runtime/asr`. Four files at [revision 08e178d](https://huggingface.co/Systran/faster-whisper-medium/tree/08e178d48790749d25932bbc082711ddcfdfbc4f) are SHA/size checked during download and image build. The image makes only public model files readable by its non-root execution user and runs an offline permission/dependency check. Weights remain ignored and must not enter exported user projects.

Set `VIDEO_ASR_MODEL=Systran/faster-whisper-medium`, `VIDEO_ASR_IMAGE_REF` to the actual built image ID, and `VIDEO_ASR_RUNTIME_DIGEST` to its 64 hex characters. Medium uses CPU int8, 4 CPUs, a 6 GiB container limit and a 300-second execution deadline. The host must have adequate free memory. This deadline does not authorize a retry of an unknown invocation. The model reported by the recognizer must equal the configured identity; cache keys retain both that identity and the immutable runtime digest. Existing small runtime keys are preserved. Narration packages retain either actual model name without changing the expected script or timestamp checks.

`npx tsx scripts/video/probe-asr-medium-runtime.ts --medium-runtime` with the explicit medium image variables checks the six archived original WAVs through production ASR and cold journal replay. The separate full-context diagnostic retained a zero-duration word even though its text was correct; that failure cannot be counted as valid word timings. Neither a model upgrade nor these probes replaces final AAC/postmix, listening or complete film QA.
