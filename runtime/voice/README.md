# Offline voice runtime

This image generates a fresh WAV from each trusted `job.json`. The model and two voices are downloaded only at build preparation time; they are not committed to Git. The running container has no network and receives no model API key.

Run `python3 runtime/voice/fetch_model.py`, then `docker build -t videobuddy-voice:local runtime/voice`. Record `docker image inspect videobuddy-voice:local --format '{{.Id}}'` and set `VIDEO_VOICE_IMAGE_REF` to that `sha256:...` ID and `VIDEO_VOICE_RUNTIME_DIGEST` to its 64 hex digits. Run `npm run probe:video:voice -- --record` with those variables. Rebuild and reprobe when the model, package or Dockerfile changes.

`fetch_model.py` pins the ONNX repository revision and checks every file's SHA-256. The image uses `@uzen/kokoro-js@1.2.4`, one Chinese voice (`zf_001`) and one English voice (`af_maple`). See [model card](https://huggingface.co/onnx-community/Kokoro-82M-v1.1-zh-ONNX) and [upstream model card](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh) for the stated Apache-2.0 model license. The npm package is also Apache-2.0; preserve package license notices when distributing the image.

Mandarin uses the pinned `misaki[zh]==0.9.4` reference frontend; all nine Python runtime dependencies and release hashes are locked in `requirements.txt`. Source-build tools are separately locked in `build-requirements.txt`; installation disables isolated downloads and verifies the complete installed dependency set with `pip check`. The local tone adapter preserves dictionary tones in compound lexical words ending in 的/地/得, while retaining neutral grammatical particles. This addresses the demonstrated 大地/土地/目的地 errors; it does not establish correct pronunciation of every ambiguous word or proper name. See [upstream Mandarin frontend](https://github.com/hexgrad/misaki/blob/main/misaki/zh.py) and [tone sandhi](https://github.com/hexgrad/misaki/blob/main/misaki/tone_sandhi.py). Misaki is Apache-2.0; retain its and its dependencies' packaged license notices when distributing this runtime.

Embedded English fragments are discovered by running that same reference frontend's numeric and punctuation normalization, then converted by the original npm English frontend. The resulting phonemes use the original Kokoro tokenizer and acoustic model. English voice requests retain their original native path. Inputs exceeding the model token limit fail before synthesis instead of truncating narration. Build-time `node --test test/phonemes.test.mjs` runs without network and intercepts the acoustic model: these are frontend tests, not listening or ASR evidence.

The final image uses the same digest-pinned Python bookworm base as the independent ASR image, copying Node 22.23.1 and its npm package from the Node build stage. This avoids installing Python through unpinned Debian package indexes. Python packages verify their pinned release hashes; runtime containers remain offline.

This runtime produces 24 kHz mono float WAV. The separate pinned media image places verified lines on a 48 kHz narration-only track. Word timings, ASR, music/foley, loudness mastering and listening QA remain necessary before publishing video.
